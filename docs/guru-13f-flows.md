## ★ 예측 도구가 아니다

같은 데이터로 만든 시그널 8종 × 호라이즌 3개(24조합)를 이벤트 스터디로 검증한 결과
**전부 `|t| < 1.7` 로 통과 0** 이었다. 정보량이 0 인 난수 시그널이 `|t| = 1.563` 을
뽑아 실제 최고치(1.681)와 구분되지 않았다.

즉 **"거장들이 동시에 샀다"는 사실에서 초과수익을 기대할 근거는 확인되지 않았다.**
이 화면은 "무슨 일이 있었나"를 보는 조회 도구다. 매매 판단으로 직결시키면 안 되고,
UI 문구에도 예측 뉘앙스를 넣지 말 것.

## 읽는 법

### gross 와 net 을 반드시 같이 본다

- `gross_bp` = Σ|Δwgt| — 조정 **총량**, 방향 상쇄 없음
- `net_bp` = ΣΔwgt — 조정 **순방향**
- `agreement` = |net| / gross — **1 이면 전원 같은 방향, 0 이면 정확히 갈림**

실측(2025-12-31 → 2026-03-31)에서 **GOOGL 은 15명이 조정해 1위였으나 agreement 0.09**
였다. 10명이 사고 5명이 팔았다. movers 만 보면 "최대 합의 종목"으로 오독한다.
반면 ASML 은 6명뿐이지만 agreement 1.00 으로 전원 같은 방향이었다.

### 절대값이 아니라 평소 대비로 본다

`movers` 옆의 `movers_baseline` 은 과거 8개 분기쌍에서 그 종목을 조정한 거장 수의
평균이다. 거장 20명이 늘 들고 흔드는 대형주는 5명이 평상시 수준이고, 아무도 안
건드리던 종목은 2명만 움직여도 사건이다.

| 종목 | movers | baseline | 해석 |
|---|---:|---:|---|
| MSFT | 10 | 9.7 | 총량 1위지만 **평소 수준**(백분위 29%) |
| V | 8 | 2.9 | 평소의 2.8배 — **진짜 이례** |
| ASML | 6 | 2.7 | 이례 + agreement 1.00 — 가장 강한 신호 |

`is_unusual` 은 "과거 어느 분기보다 많고 **동시에** 평소의 1.5배 이상"일 때만 선다.
`movers_n_obs` 가 3 미만이면 `movers_baseline` 은 `null` 이다. **표본이 없으면
판단을 유보하지, 숫자를 지어내지 않는다.**

## 조용히 틀리는 지점 (전부 실제로 밟았음)

### 1. 최신 분기를 그냥 쓰면 안 된다

13F 공시기한은 분기말 + 45일이다. 마감 직전에는 최신 분기 제출률이 한 자릿수다.
실측 2026-08-11 기준 **2026-06-30 분기는 23명 중 1명(4%)만 제출**한 상태였고,
그대로 비교하면 참여 거장 1명짜리 "합의"가 만들어졌다.

`pick_periods()` 가 제출률 50% 미만 분기를 건너뛴다. 응답의 `period_meta` 에
분기별 제출률이 들어 있고 UI 가 `2026-06-30 제출 4% · 집계 제외` 로 표시한다.

같은 이유로 `guru13f._build_roster()` 도 고쳤다. 종전에는 "가장 늦은 period" 를
기준으로 잡아 **roster·consensus·turnover 가 모두 비고 웹 상단 3카드는 쿼리조차
뜨지 않았다**(페이지 전체 공백).

### 2. value 를 거장 간에 더하면 안 된다

13F 는 value 단위가 섞여 있다(관측 68.7% 가 천달러). 그대로 합산하면 천달러
신고자가 1000배로 잡힌다. **항상 거장 × 분기 단위로 `wgt = value / Σvalue` 를
재계산**해 bp 로만 비교한다. `holdings_13f.wgt` 컬럼이 채워져 있으나 산출 근거를
신뢰하지 않고 다시 만든다.

### 3. 한 분기만 낸 거장을 섞으면 안 된다

직전 분기를 안 낸 거장을 넣으면 그 거장의 **보유 전 종목이 신규 편입으로** 잡혀
편입 합의가 통째로 부풀려진다. `_participants()` 가 양 분기 모두 제출한 거장만
쓰고, 빠진 거장은 `excluded` 로 반환한다.

### 4. 섹터 매핑률이 분기마다 다르면 미분류가 거짓말을 한다

13F 원문에도 DB 에도 섹터가 없다. `cusip_ref` 는 cusip/name/ticker 뿐이라
**외부 매핑을 주입**해야 한다(`assets/guru_sector_map.csv`, CUSIP 키).

처음에 매핑 CSV 를 **최신 분기 상위 종목으로만** 만들었더니 직전 분기에만 있던
종목이 전부 미분류로 잡혔고, 그 결손 차이가 **"미분류 −14,147bp 대량 감소"** 라는
가짜 이동으로 나타났다. 커버리지가 82.3%(prev) vs 88.7%(curr) 로 6.4%p 어긋났고,
6.4%p × 10000bp = 640bp 가 관측된 거장당 −643bp 와 정확히 일치했다.

→ 두 분기 합집합으로 매핑을 확장해 격차를 **0.6%p** 까지 줄였다.
→ 응답에 `coverage_prev` / `coverage_curr` / `coverage_gap` 과
  **`unclassified_unreliable`** 플래그를 실어, 격차 1%p 이상이면 UI 가 경고하고
  미분류 행을 흐리게 만든다. **격차 1%p = 거장당 100bp 의 가짜 이동이다.**

### 5. ticker 를 경유하면 안 된다

CUSIP → ticker 매핑률이 낮다(상위 300종목 중 179개). 섹터 매핑은 **CUSIP 을 키로**
쓴다. 다행히 보유가 극도로 집중돼 있어(상위 100종목 = 비중 75.8%, 300종목 = 93.6%)
355행짜리 CSV 로 비중 기준 91.5% 를 덮는다.

## 모집단이 화면마다 다르다

- 기존 카드(포트폴리오·컨센서스·턴오버) = `DEFAULT_ROSTER_CIKS` **승인 9인**
- 변동 분석 = `GURU_BY_CIK` **큐레이션 23인** (실제 참여 22인)

의도한 차이다. "몇 명이 동시에 움직였나"는 모집단이 넓을수록 의미가 있고 9인으로
좁히면 `movers 15` 가 나올 수 없다. 혼란을 막으려고 카드 배지에 **"큐레이션 거장
22인 참여"** 로 명시했다. 9인으로 통일하려면 `_build_flows()` 의 `ciks` 한 줄만 바꾸면 된다.

## 섹터 매핑 CSV 관리

`apps/collector/collector/assets/guru_sector_map.csv` — `cusip,sector,ticker,name,agg_bp`.
로더는 `cusip` 과 `sector` 만 읽는다(나머지는 사람이 읽기 위한 열).
환경변수 `GURU_SECTOR_MAP` 으로 경로 교체 가능.

갱신할 때 **빈 sector 행을 채우는 것**과 **새 행을 추가하는 것**을 모두 해야 한다.
한 번은 `if cusip in have: continue` 로 기존 행을 건너뛰어, 채워야 할 빈칸을
정확히 건너뛴 적이 있다(신규 20개만 추가되고 빈칸 100여 개가 그대로 남음).

이름 키워드 추론은 편하지만 오분류가 난다. 실측에서 `POWER SOLUTIONS INTL`(엔진·
발전기 제조사)이 "POWER" 때문에 유틸리티로 갔다. 키워드를 쓰면 **반드시 위험군을
눈으로 감사**할 것.
